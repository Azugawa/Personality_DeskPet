## 1. 为什么选择“正面偏斜的斜投影”

现有角色只有一张**正面**像素图，没有侧面、背面、3/4 视角或坐姿。

因此不能：

- 把整张人物 PNG 旋转来假装转身；
- 把整张人物 PNG 斜切来假装透视；
- 把镜像当成真正的左/右 3/4 视角；
- 假设已经有坐下、搬运或行走的部件。

本阶段采用的统一视觉方向是：

> **正面偏斜的正交斜投影（front-biased orthographic oblique）**
>
> 人物保持正面 billboard；家具的正面朝向镜头，顶面后退，右侧面可见。
> 所有物体共享同一个地面轴、同一像素比例和同一套假透视。

这不是机械旋转 45°。当前深度投影角为：

```text
depth_axis = (0.55, -0.35)
屏幕角     ≈ 32.5°
```

选择较小角度而不是 45°，是为了：

- 保持桌面和椅面的可读面积；
- 不让桌椅顶面吃掉角色身体；
- 让像素块的尺寸关系仍然清楚；
- 与正面人物 billboard 的差异最小化。

## 2. 坐标与投影公式

### 2.1 三种坐标

| 坐标 | 含义 | 方向 |
|---|---|---|
| `x` | 地面横向 | 屏幕向右 |
| `depth` | 地面纵深 | 越大越远离镜头 |
| `z` | 高度 | 向上 |

### 2.2 地面投影

```text
screen.x = x_origin + x + depth * 0.55
screen.y = front_y + depth * (-0.35)
```

当前常量：

- `x_origin = 0`
- `front_y = 660`
- `max_depth = 200`

例如：

| 物体 | 地面坐标 | 屏幕锚点 |
|---|---|---|
| standing 人物 | `(320, 0)` | `(320, 660)` |
| workspace 人物 | `(170, 0)` | `(170, 660)` |
| 椅子 | `(330, 25)` | `(343.75, 651.25)` |
| 桌子 | `(415, 75)` | `(456.25, 633.75)` |

所有“地面接触点”必须通过这个公式得到，不能在脚本里另写一套屏幕坐标。

### 2.3 高度投影

```text
screen.y -= z
```

盒子局部坐标：

```text
Vector3(x, depth, z)
```

家具 profile 中的 `box.origin` / `box.size` 都使用这个局部坐标。
物件的 `position` 是它**地面锚点的屏幕位置**。

### 2.4 正交，不做近大远小

本阶段**不使用透视缩放**：

- 同样的 100 px 高桌腿，在 depth=0 和 depth=150 都画 100 px 高；
- 远近只通过屏幕 y 位移、遮挡、阴影和图层表达；
- 人物和家具不会因为 depth 改变 scale。

这样可以保持像素尺寸一致，也避免人物和家具的像素颗粒互相冲突。

### 2.5 屏幕示意

```text
         屏幕上方
              │  +z（高度，向上）
              │
              │        +depth（地面向远处）
              │      ↗  屏幕位移 (0.55, -0.35)
              │    /
              │  /
              └────────────→ +x（地面横向）
         屏幕下方

地面：screen = (x + 0.55 * depth, 660 - 0.35 * depth)
高度：再减去 z
```

## 3. 地面与预览网格

`Main` 在预览模式下绘制一个**仅用于构图验证**的地面网格：

- 它和家具/人物使用完全相同的 `Pseudo3D` 投影；
- 它使用平涂色，没有渐变；
- 调试网格线宽：横向 depth 线 1 px，纵深 lateral 线 2 px（仅为屏幕可读性，不是正式美术线宽）；
- 它在桌面透明模式下随 `BackdropLayer` 一起隐藏；
- 它不是背景美术资产，也不是正式房间。

地面范围：

- `front_depth = -120`（镜头前方的地面）
- `back_depth = 200`
- 深度网格步长 25，横向网格步长 80
- 主要网格线每 100 深度 / 160 横向
- `depth = 0` 的地面线加亮，人物脚底就在这条线上

因此：

- 人物脚底 `y=660`，位于 depth 0 的线上；
- 椅子 depth=25，桌子 depth=75，都落在地面内；
- 阴影可以越过脚底向下延伸，仍落在地面上。

## 4. 人物规则

### 4.1 当前可用的唯一视角

人物配置明确记录：

```json
"available_views": ["front"]
```

缺失方向：

- `back`
- `front_right`
- `front_left`
- `right`
- `left`
- `back_right`
- `back_left`

缺失状态：

- `sitting`
- `carrying`

因此本阶段：

- 只显示正面站立的完整 PNG；
- 人物是正面 billboard，**不旋转、不斜切**；
- 脚底使用 content bounds 的底部中心；
- 缩放固定 `0.25`，最近邻过滤；
- 阴影独立挂在 `Character/ShadowRoot`；
- 不允许用整图旋转或镜像冒充 3/4 转身。

`Character.set_facing("left"/"right")` 目前只能镜像正面图，并会输出警告；
它不能被视为已经拥有侧面素材。

### 4.2 脚底与地面接触

- 人物根节点位置 = 地面投影后的脚底中心；
- `FullBodySprite` 的锚点来自 profile 的 `content_bounds`；
- standing：脚底 `(320, 660)`，depth 0；
- workspace：脚底 `(170, 660)`，depth 0；
- 接触阴影围绕脚底，偏移 `(8, 4)`，不使用模糊渐变。

判断标准：脚底像素与 depth 0 地线重合，阴影在脚下，不是悬空或陷入。

### 4.3 当前阴影

人物阴影为独立 `ShadowView` 节点：

- 形状：椭圆
- 尺寸：`224 × 36`
- 颜色：`#00000066`
- 内核：`#00000040`，`core_scale=0.62`
- 相对人物 z：`-5`

阴影不是烘焙进人物 PNG 的，后续可单独调整。

### 4.4 方向表规划（是否需要八方向）

后续动画需要人物 45°（3/4）镜头。对固定斜投影相机、人物可在地面自由移动/转身的
桌宠，**建议按 8 方向规划**，但**按需分阶段制作**，不要一次性产出全部方向的所有动作。

地面 8 个朝向（相对当前相机，depth 为右上后退）：

| 朝向 | 含义 | 优先级 |
|---|---|---|
| `front` | 面向镜头（默认站立/互动） | 高 |
| `front_right` (FR) | 3/4 前-右 | 高（45° 主视角） |
| `front_left` (FL) | 3/4 前-左 | 高（45° 主视角） |
| `back` | 背向镜头 | 中 |
| `right` / `left` | 纯侧面 | 中（横向移动） |
| `back_right` (BR) / `back_left` (BL) | 3/4 背-右/背-左 | 低（必要时） |

- **45° 镜头的最小可行集**：`front_right` + `front_left`（可先做其一）+ `front` + `back`；
  纯 `left/right` 与背向对角可在真正做行走/搬运时再补。
- **镜像规则**：`front_left/right`、`back_left/right`、`left/right` 若素材在光照/肢体上
  不对称，**不要简单镜像复用**；像素风 3/4 视图通常需要左右各一套，或刻意设计成对称。
- **成本**：每个方向都要乘上状态（idle/walk/sit/carry…）与帧数，因此方向表必须
  在动画制作前冻结，避免中途加方向重做。
- **命名/存储**：方向加入人物 profile 的 `available_views` / `missing_views`；
  `sitting` / `carrying` 属于状态，放进 `missing_states`；动画层按 `state + direction + frame`
  组织，不要写在场景切换代码里。

> 待决定：当前环境是“正面偏斜”（家具只露出顶面 + 右侧面）。若要让家具与人物 45° 视角
> 完全一致，下一阶段应把环境投影升级为真 3/4（露出两个侧面），否则人物 3/4 与家具
> 正面偏斜会有轻微风格差异（可作为 billboard 风格接受）。人物方向表无论选哪种都建议按 8 方向预留。

## 5. 家具规则

### 5.1 家具不是单张平面图

本阶段没有真实桌椅 PNG。为避免伪造“已存在素材”，workspace 使用
**profile 驱动的调试盒体**：

- `kind = "debug_pseudo3d"`
- `parts[]` 里每个盒体有独立的 `origin`、`size`、`material`、`draw_order`
- 全部使用统一投影和调色板
- 桌/椅都有明显 `DEBUG ... / PLACEHOLDER` 标签与洋红地面锚点
- 这些不是最终家具美术

> 像素密度说明：调试盒体使用 1 px 轮廓的 **schematic blockout**，用于验证空间/遮挡，
> 不是最终像素密度基准。正式家具素材必须匹配人物当前约 16 屏幕像素的像素块尺度、
> 轮廓重量和有限调色板，不能直接以调试盒体的细线作为最终风格。

家具 profile 同时记录：

- `dimensions`
- `anchor`
- `parts`（桌面、桌腿、背板、椅面、椅背等）
- `shadow`
- `debug`

因此“桌子/椅子在不同场景中结构或尺寸无故改变”是不允许的：
场景只能引用同一个 profile，并改变 `ground_position` / `z_index` / `visible` 等摆放参数。

### 5.2 盒体绘制

每个盒体只画三个可见面：

1. 右侧面（在 depth_axis.x≥0 时）
2. 顶面
3. 正面

颜色规则：

- 顶面最亮
- 正面中间
- 侧面最暗
- 1 px 深色轮廓
- 只用平涂色，不做渐变、不做大面积模糊

绘制顺序：

```text
后腿 → 背板/椅背 → 桌面/椅面 → 前腿
```

这是家具内部的 `draw_order`，与场景中不同物体的 z_index 是两套层级：

- 物体之间的前后由 z_index / depth 决定；
- 物体内部的部件由 profile 的 draw_order 决定。

### 5.3 当前家具尺寸与锚点

| 家具 | 宽 × 深 × 高 | 地面锚点 | 部件数 |
|---|---:|---|---:|
| 调试桌 | 210 × 100 × 148 | 前边中心 `x=105, depth=0, z=0` | 6 |
| 调试椅 | 84 × 84 × 142 | 前边中心 `x=42, depth=0, z=0` | 6 |

桌椅底部接触点都在 z=0 的地面上，桌腿/椅腿没有悬空。

### 5.4 家具阴影

- 使用 `ShadowView` 的 `footprint` 形状；
- 按地面的宽 × 深投影，不是屏幕正圆；
- 桌子：`230 × 112`，偏移 `(10, 6)`
- 椅子：`100 × 96`，偏移 `(8, 5)`
- 都使用半透明平涂和更小的内核，没有渐变
- 阴影层相对家具 `z=-2`

## 6. 遮挡与深度排序

当前 workspace 的深度链：

```text
人物 depth 0   z=50   ← 最近镜头
椅子 depth 25  z=40
桌子 depth 75  z=30   ← 最远
```

规则：

- depth 越小，z_index 越高；
- z_index 高的物体遮挡 z_index 低的物体；
- 三个物体在屏幕上有重叠，形成可检查的遮挡链：
  - 人物在椅子上方；
  - 椅子在桌子上方；
  - 椅子遮挡桌子左侧；
  - 人物遮挡椅子左侧边缘。
- 这套关系已经写入测试：检查 depth 顺序、z 顺序和屏幕矩形重叠。

阴影的层级：

- 人物阴影相对人物 `-5`；
- 家具阴影相对家具 `-2`；
- 阴影仍是独立节点，可以被场景层级遮挡，不使用模糊。

> 新增场景时，必须同时检查“depth 顺序”和“z_index 顺序”。
> 只改其一会出现视觉上前后矛盾。

## 7. 像素风规则

- 所有纹理使用**最近邻**过滤。
- 人物纹理 2048×2048，显示 scale 0.25；家具用设计像素 1:1。
- 所有投影点 `round` 到整数像素，避免半像素模糊。
- 不使用 2D MSAA/平滑缩放。
- 不使用大面积渐变、软笔刷、模糊阴影。
- 轮廓 1 px（预览地面网格的调试线宽例外，见第 3 节）。
- 每个材质最多三档平涂明暗 + 轮廓色。
- 调色板集中在 [pseudo3d.json](../config/visual/pseudo3d.json) 的 `palette`。
- 不允许为了局部效果修改原始人物 PNG。

## 9. 新场景/新家具的验收清单

新增任何场景或家具前，逐项检查：

1. 地面接触点使用 `ground_position`，没有手写屏幕坐标。
2. depth 与 z_index 顺序一致（近高远低）。
3. 角色脚底在 depth 0 或明确的地面网格线上。
4. 家具和人物的正面朝向一致；没有为了“看起来 3D”旋转整张图。
5. 家具部件内部 draw_order 正确：后腿/背板在桌面/椅面之前，前腿之后。
6. 阴影是独立 `ShadowView`，没有模糊/渐变。
7. 所有可见面只有顶/正/侧三块平涂 + 1 px 轮廓。
8. 最近邻和整数像素没有被破坏。
9. 新增视角/动作有真实素材；没有素材就记录缺失，不伪造。
10. 重新运行测试和截图检查遮挡。

## 10. 当前缺失素材与最小补充需求

### 人物

现有：正面站立全身 PNG，12 个 provisional 部件全部 `NEEDS_REVIEW`。

最小补充：

1. **右 3/4 / 左 3/4 站立**（至少一个方向）+ 背面站立；
2. **坐姿**：髋/膝/脚有明确接触点，最好有独立大腿、小腿、脚；
3. **搬运动作**：手臂前伸/抬起，手部有可挂载物体的锚点；
4. **行走帧**：至少 2–4 帧，脚底接触点可追踪；
5. 若要做真正的部件动画：人工确认分割并导出正式 `parts/`。

没有这些素材时，不能宣称“角色可以转身/坐下/搬运”。

### 家具

现有：debug profile 盒体，不是最终美术。

最小补充：

- 与当前正面偏斜投影一致的真实桌椅 PNG；
- 或分离部件：桌面、桌腿、背板、椅面、椅背、椅腿，带透明背景和 pivot；
- 桌面/椅面的透视角度、像素尺寸、光照方向必须与当前规范一致；
- 不能从其他视角素材直接旋转/拉伸使用。

### 背景

- 与同一地面/深度轴一致的房间背景（可选）；
- 若使用背景，仍需保证透明桌面模式或明确背景策略。

## 11. 下一阶段运动规则

实现人物/桌椅运动时，必须继续遵守：

### 人物移动

- 位移只改 `x/depth`，不要改 z 来“漂移”人物；
- 脚底始终落在投影地面点上；
- 影子跟随脚底，保持独立节点；
- 深度变化时更新 z_index，保持遮挡链；
- 转身必须换用已授权的 3/4/侧/背素材，不能用整图旋转或镜像冒充；
- 走动帧的脚底接触点要对齐地面，不能上下抖动。

### 桌椅移动/搬动

- 家具作为有部件的组移动，部件相对位置不应无故变化；
- 家具底部/腿部接触点保持地面；
- 阴影跟随 footprint，不旋转成屏幕椭圆；
- 搬动时角色手部锚点与家具挂载点对齐；
- 家具 z_index 随 depth 更新，遮挡关系不能靠硬编码顺序；
- 不允许把家具整体旋转 45° 来适配新场景。

### 坐下

- 需要坐姿素材/已确认的腿部部件；
- 髋部锚点对齐椅面，脚底保持地面；
- 人物与椅子的前后关系明确（坐在椅子前还是后），z_index 按 depth 更新；
- 不能用整图旋转或缩放模拟坐下。

### 事件/动画层

- 运动由独立 AnimationController/状态机驱动；
- 场景切换仍由 SceneManager 与配置负责；
